## Contract extraction and parity gaps

The route/method inventory and top-level guard requirements are recorded above for all 94 source controller operations. Team-member, school, subject, student, folder, student-query, users, analytics, test authoring/listing, and the student test-access/attempt discovery slice were inspected and implemented with authored feature tests. The test access coverage exercises active/suspended folder grants, safe question redaction, attempt discovery, persistence of initial attempts, expiry checks, duplicate request rejection, and submitted-state rejection. Test authoring coverage includes strict DTO types/whitelisting, transactional folder links, audit creation, source-shaped list relations, and parser output. The preview implementation lacks scanned-document OCR and complete source arithmetic/table analysis and is therefore explicitly partial. Tests are authored but could not be executed without PHP/Composer. Query create/reply do not emit source-style SSE revision notifications because `/api/student-data/events` is not implemented; access requests likewise do not notify the `my-tests` stream. The migrations cover the attempt state and attachment metadata required by the student read/access routes, but upload/serving, test submission, grading, and related routes remain incomplete. The analytics migration creates only the tables and fields required for those endpoints, not all course/testing/content features. The users endpoints use the existing `users`, `devices`, and role-assignment schema; no migration was needed. Multipart cover upload/clear and related storage serving are omitted. Exact DTO constraints, statuses, filtering/pagination, and side effects for other unported domains still need line-by-line extraction. Do not infer success payloads from UI types.

The source `AiNotebookService.embed()` currently posts to local Ollama `/api/embed` and fails the operation when embedding requests or vectors are invalid; no lexical retrieval fallback was found in that method. The cloud client is not yet a notebook integration and its provider/API compatibility must be confirmed before indexing or queries are enabled.
